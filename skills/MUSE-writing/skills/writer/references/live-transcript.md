# 实况记录契约

实况演出的场景有一份实况记录 `pipeline/stage/scene_{scene_id}/transcript.yaml`：舞台按回合记下人物在这一场里实际做了什么、说了什么、谁听见看见。本文件是 writer、reviser 与 manuscript-reviser 消费它的共同契约；派发说明本场实况演出时读取。

## 记录里有什么

`turns` 按发生先后排列，每条有序号 `n` 与类型 `kind`：

| kind | 字段 | 含义 |
|---|---|---|
| `turn` | `actor`、`does`、`says`、`to`、`heard_by`、`seen_by`，可选 `inner`、`silent`、`leaves`、`to_text` | 人物的一个回合：自己的动作、说出口的话、对谁说、谁听得见看得见；`inner` 只属于 POV 人物；`silent` 是只看不动，`leaves` 是离场；`to_text` 是人物写的原样对象 |
| `event` | `text`、`perceived_by` | 主控注入的世界事件及谁感知到 |
| `enter` | `actor`、`view`、`arrival`、`perceived_by` | 迟到者登场：他看到的场面、在场者看到他到来的样子 |
| `line` | 同 `turn`，另有 `after` | 写作时向人物补索的一句，接在第 `after` 条之后，列表中已排在该位置 |

`heard_by` 与 `seen_by` 是当时在场者的 slug 列表。人物显示名在其角色包的 `build-meta.yaml`。

## 发生与讲述

实况记录是"发生过什么"的记录。正文可以省略其中的事，省略不改变它发生过；正文不写与记录相反的事实，例如让没听见的人知道那句话的内容，或让没发生的事发生。确需改变事实时，回报主控，由主控取得授权并更新人物记忆。

writer 拥有进入点、叙述次序、省略、详略与叙述声音。贴身 POV 只写 POV 人物当时能感知或推断的部分：他没听见的话按他实际感知到的写（看见对方压低声音说话、听不清内容），他看不见的动作不进他的意识。

## 人物原话受保护

记录里人物说过的话保持原来的意思、立场和口气；人物没说过的话不替他说；`inner` 的内容只属于说它的人，只能经由他的意识进入正文。在此之内：

- 台词可以整句删去、截取其中一段、去掉重复，也可以拆进动作之间、接入叙述；不改写措辞，不把两人的话合成一人的。
- `does` 记的是人物自己选的动作。动作的写法由 writer 决定，动作本身不换成另一种选择。
- `to_text` 保留人物原本写的对象，例如同时说给两个人听。

需要新台词衔接时，writer 不自己写，在最终回复里提出索句：接在第几条之后、此刻那个人物面对什么（用故事内的话写），例如"接在第 7 条之后：杜芷方刚把封条按在桌沿，沈砚舟还没开口"。主控取回人物的回答、记入实况记录后，让 writer 接着写。

## 修订者

reviser 与 manuscript-reviser 把实况记录当受保护来源读：修订可以删去或压缩人物原话，改写原话须有与改变故事事实同等的授权。修订改变了已发生的事（谁在场、谁听见、某件事是否发生）时，在修订摘要里写明场景与改了哪项事实，主控据此更新人物记忆；修订者不改舞台文件。

## 核对方式

保全靠 writer 交稿前自行对照；scene-reviewer 在既有人物声音判据下可以读记录作依据。作者裁决不配脚本逐句核对：校验脚本会让执行者把精力花在一致性核验上。
