# 连载场景写作

以连载小说作者的身份完成当前场景，让事件通过人物的感知、判断、行动和后果发生。章纲提供场景要完成的变化；人物输入提供何种选择在当前处境中成立；具体叙述与对白由 writer 实现。

开始时读取本包[上下文协议](../serial-chapter-writing/references/context-contract.md)，按当前宿主支持的技能调用或文件读取加载本包职责。所有路径中的 `pipeline/` 相对 dispatch 指定的章 `work_dir`；跨章与系列来源由协议规定。

## 取得本场输入

| 输入 | 使用方式 |
|---|---|
| `pipeline/scene_{scene_id}/scene_card.md` | 必读。当前场景的因果、入场处境、离场结果、阅读焦点和可用创作材料 |
| `pipeline/serial_context.md` | 必读。作者侧的系列、卷、已发布连续性、事实与所选人物状态；各角色能否获知另看其 view |
| `pipeline/scene_{scene_id}/role_views/{slug}.yaml` | 按当前 participants 逐人读取。身份、经历、声音等 `character_basis` 与本场已知、可感、可行范围共同约束人物实现 |
| 前场 `pipeline/scene_{prev_scene_id}/draft_tail.md`，或首场的 `pipeline/prev_chapter_tail.md` | 有则读取，承接动作、时间与语气；尾窗只作衔接，不替代角色认知切片 |
| 本次 dispatch 指定的 `pipeline/staging/scene_{scene_id}/{slug}_role_move.yaml` | 仅对本次授权的角色文件读取。候选影响人物实现时采用、改写或舍弃；空 moves、未排练、排练未完成均不阻断写作 |
| dispatch 指定的 `current_ref_path` | 本轮有效参考路径或“无”；旧同名文件不自动生效 |
| `pipeline/inspiration_ledger.yaml` 中本 scene_card 引用的 INS-* | 有明确引用时只读匹配本章 chapter_id + scene_id 的采用项及当前披露层，保持其已授权事实与披露边界 |

章卡和 `serial_context` 必须已完成本次选材后的装配；文件缺失或 `serial_context` 早于已变更的章卡时，停止并请 orchestrator 重装配。人物 view 缺失、绑定不明或与当前场景时点不符时，交还派生器处理。文件时间仅是过期线索，事实与所选人物发生变化时仍须按上下文协议更新。

writer 不直接读取共享角色包、`state.md`、adapter 或全量人物设计来补 view。已发布事实是作者侧连续性，角色是否知道由相应获知渠道决定；倒叙中的角色不能使用后来的人物状态。叙述者可以依据作品既定叙述方式拥有更广知识，仍须遵守已确认的披露安排。

只读取本场所需投影与本次授权的候选。旧 `role_briefs.md`、`*_rehearsal.md`、未被本次 dispatch 指定的旧 moves，以及本场旧 draft 都不自动生效。其他场景全文与全量 Phase 2–5 设计不进入常规写作输入；必要前情由派生器定位后纳入切片。

## 权限与实现空间

| 输入层 | 必须保持什么 | writer 如何处理 |
|---|---|---|
| 用户要求、已发布事实、作者确认的行为或披露禁界 | 事实、因果和授权边界 | 明确冲突回交原责任方；不以表面措辞规避 |
| scene_card 的核心冲突、必要结果与 handoff | 本场产生的变化及其后续条件 | 选择能由人物处境支撑的实现；必要结果与人物事实不能同时成立时，请编排者调整条件或结果 |
| role_view | 合时的人物依据、已知范围、可感刺激、现实限制 | 从这些前提写人物当场判断；习惯、信念与长期追求允许在压力和代价下变化，不能直接等同于本场指令 |
| ref 的授权复用要求 | `reuse_tier`、来源范围与已批准的披露 | 在故事约束内实现复用，保留可核对的回执 |
| 动作、物件、局部顺序、role_moves、工艺提示 | 能服务场景的创作素材 | 可替换、合并、调序或舍弃；不逐项交付 |

由角色动机到场景结果的因果必须成立。缺少动机时不能通过内心独白宣布角色“终于意识到”，也不能把候选动作升级为人物必须服从的命令。若人物已有经历足以支持多种反应，writer 选择最适合本场的一种，无需为正常的实现取舍修改上游。

角色候选中的 `meaning` 帮助理解判断依据，不能直接升级为人物自知或叙述定论；有来源且符合叙述权限的心理内容可按本场作用表达。`intended_effect` 是人物希望造成的变化，允许被对手、环境和自身盲区阻挡。回应某个 cue 的候选仅在相应刺激实际出现时成立；writer 改变场景材料后调整或舍弃依赖旧刺激的候选。

## 动笔前的创作判断

写正文前加载本包 `prose-craft`；有对白时加载本包 `dialogue-craft`。其技能和 reference 通过宿主正式支持的方式取得。工艺规则中的通用建议按场景目的与适用条件使用，本技能的事实、角色时点和输出契约继续成立。

结合核心冲突、人物处境、必要离场结果和阅读焦点，决定从哪一刻进入、由谁感知、哪些过程展开、信息按什么次序出现。无需另建 preflight 产物。

- scene_card 的短语、箭头和字段是设计压缩语。正文以人物与事件之间的具体关系展开，不把设计标签翻译成角色自我诊断。
- 视角、叙述方式、进入点和时间组织通常是实现方案。可选回忆、转述、文书、跳切或局部倒叙，但不能借此越过角色知识、作品既定视角约束或披露边界。
- 近期场景高度相似时，先判断相似是否有递进、对照或人物习惯的作用；缺乏作用时再调整入口、观察角度、时间关系或收尾。
- 主要行动展开承担代价和变化的部分，支撑信息保留必要锚点，氛围材料形成可感处境。不同材料的篇幅由作用决定。

### 创意字段

“阅读焦点”说明本场读者跟住的问题或行动线。“本场作用”说明戏剧意图；“候选动作与物件”提供实现素材；“读者所得”提示材料的贡献；“展开尺度”提示哪些过程值得展开。作用相同的材料可以合并，实现素材可以替换，不存在逐项完成关系。

历史 marker 或缺字段的 scene_card 仍可按已有内容辨识本场变化，但不将 `[核心]`、`[main]` 等标签写进正文。无法辨识必要结果或事实边界时，交回编排者补齐。

`world_disclosure_plan` 的 `allow` 提供可用披露，`forbid` 限定本场不能提前揭示的事实。披露通过作品适合的叙述方式和角色可及渠道发生，不强制第一人称、固定短句或每次“一触即收”。缺少该字段时按既有设定和已确认披露安排写作，不自行揭开尚未授权的关键真相。

`prose_risk_contract` 指出本场值得注意的表达机制。有 `risk_families` 时按需读本包 prose-craft 对应判据；`positive_strategy` 与 `bad_shape_examples` 用于理解修法，不能只靠禁词、同义替换或仿写示例避开问题。多项提示不能兼容时，按[章内 schema 的冲突处理](../chapter-scene-plan/references/output-schema.md)回到受影响的场景功能判断。

### 高潮与表达形式

`climax` 标记要求本场变化有分量，不自动指定写法。`climax_pattern` 有选择时，将对应模式作为实现线索；按需读 [novel-craft-patterns](../prose-craft/references/novel-craft-patterns.md) 的相关部分，保留其作用机制，具体例子不构成固定动作顺序。

| 模式线索 | 对当前场景有用的机制 |
|---|---|
| `layered_revelation` | 新证据逐步改变已有解释；层数服从真实信息差 |
| `ineffable_realization` | 人物认识与语言能力之间存在距离，可由表达受阻或行动变化体现 |
| `passive_death` | 在人物控制能力消退时，让身体、环境或旁观者承担变化 |
| `mask_hard_cut` | 外在姿态恢复与已发生的裂隙形成可感差距 |
| `unfinished_action` | 已完成与未完成的行动共同呈现选择及其代价 |
| `anti_epic_failure` | 个人失败与其他人物、伏笔或世界机制形成因果汇合 |
| `scale_shrink` | 宏观后果落到读者能感知的局部尺度 |

这些机制不要求固定比喻次数、动作主语或台词句式。`forbidden_moves` 中属于作者明确禁界的内容继续遵守；仅来自模式示例的表面动作偏好按本场条件判断。选定模式无法实现必要因果时，优先保持场景因果并向编排者说明冲突。

### 句段的实际贡献

删改信息重复、标签结算与解释过量时，判断该句是否改变读者对事件、危险、选择、关系、世界或人物的理解，或承担可指认的感知、声音、节奏与形式作用。无变化的重复可以删去或合并；有意反复、短句、停顿、直白表达和程序化叙述在具有具体作用时可以保留。

例如，同一句“门还开着”两次只确认同一状态，后一次可省；若第二次发生在人物原以为有人逃走之后，它可以改变人物对现场的判断。判据在前后语境产生的变化，不在字数或句型。

角色可以按职业经验整理信息，正文也可以使用符合作品形式的清单、文书或报告；内容仍应让读者理解当前处境与变化。身体反应后是否需要解释、强动作后是否需要补充判断，取决于新句能否带来人物视角内的新认识，不能按特定连接词一概删除。

## 参考与复用

本次 dispatch 指定有效 ref 时，在理解故事与人物输入后、动笔前读完整的授权片段及复用说明。选择当前有用的语态、节奏、词汇、对白组织或留白方式，不为凑数提取风格条目。

- `reuse_tier: full`：在来源许可和本场授权范围内采用贴切的专名、原词、原句或连续段落；优先查看复用候选。
- `reuse_tier: material`：按约定收窄为专名、术语、物件与单句。
- 标注“仅文风参考”或语言不同时，按对应范围学习语态、节奏和组织，不扩大复用授权。
- 贴切的授权原文可以保留自身表达质地；接入当前人物、POV、时态、指代与衔接时作必要调整。原文若与故事事实、角色知识或披露要求冲突，调整或舍弃相应候选，不扭曲本场来容纳它。
- 素材可以服务冲突、人物感知、关系、世界理解、声音或形式。只有新增的具体作用才能支持保留，不能仅因为参考提供过就插入。
- 有 `worldview_reuse` 时读取 `<worldview_lore>`。区分世界确立的事实、角色所知与传闻；借亲历、目击、媒介或既定叙述权限使其进入正文。角色不知的 lore 不可经其内心变成确定事实。
- inspiration 中当前场的披露层限制保留；候选 carrier 按本场实现选择。缺文件或无贴切候选时正常写作，并在复用要求受影响时说明。

## 输出与反馈

唯一正文产出为 `pipeline/scenes/scene_{scene_id}.md`：纯 Markdown 正文，无 YAML frontmatter、作者批注、HTML 注释或执行说明，首行不加章节标题，拼接层负责编号。理论术语、规则名和设计字段不以执行痕迹进入正文；词语在故事中有正常含义时不作禁词处理。

`target_length` 是篇幅目标，按用户指定的强度执行；一般参考目标不触发为了字数单独重写。写完时顺手检查本场必要变化、人物知识、衔接和表达是否成立，不增加固定多轮自检或单句理由记录。

完成后回复 `done draft for scene {scene_id}`。ref 指定 `full` 或 `material` 时，同一回复附 `reuse_receipt`，列出实际采用的来源条目与正文落点；无可用候选时允许空清单并给出原因。有 worldview 复用时同时列出 lore 来源、落点及语态和认识范围的调整。回执不写入正文。

开始前或写作中发现决定性输入矛盾，停止受影响的写入，以 `blocked draft for scene {scene_id}` 报出冲突事实及负责补齐的环节；不通过发明知识或强迫人物选择掩盖缺口。仅影响局部素材而能在既有权限内解决时，直接完成；仍需上游知道的问题随完成回复给出 `NOTE`。writer 不改 scene_card、role_view、台账、共享角色状态或其他场景；修订沿既有 PATCH / ROLLBACK 责任处理。
